# 自动化与自动回复

双端入口为设置中的“自动化”，原自动签到选项保留，新增“自动回复”。功能默认关闭，规则、扫描位置及历史任务按账号隔离，仅存于本机，不进入应用导出备份，也不同步到其他设备。

## 使用

1. 在“自动回复”添加已关注贴吧，每个吧一条规则。
2. 填写关键词（每行一个或以逗号分隔）、回复消息及0至3600秒延迟。任一关键词在标题或首楼正文中出现即命中，英文忽略大小写。回复编辑器支持现有贴吧原生表情。
3. 开启自动回复。首次检查只记录当前帖子的基线，不回复已有历史帖子；此后每60秒检查新增帖子，跳过本人发帖。
4. 安卓需要后台运行时，另开启“后台保活”并允许常驻通知；通知可直接打开任务列表或停止保活。电池策略可能影响运行。
5. iOS可开启“允许后台刷新”，由系统决定刷新时机。它不提供常驻后台实时监测。离开前台后只使用短暂合法运行时间及系统后台刷新，不以音频或定位伪装保活。

正常启动界面后等待8秒再开始补扫，按上次记录逐页检查更新，不阻塞首屏加载。未命中不会产生提醒；中断期间命中的任务进入“待确认”，弹窗只引导查看，点击每条任务的“同意回复”后才重新计算延迟并发送。“稍后”仅关闭提醒，任务仍在历史列表，可随时确认或忽略；已展示的提醒不会因为重复启动反复弹出。

## 历史任务与原帖

列表包含贴吧、帖子标题、命中词、回复内容快照、发现时间、计划发送时间及结果说明。状态包括待确认、等待发送、正在发送、已发送、发送失败、结果待确认和已忽略。每条均有“打开帖子”；iOS在成功回执包含回复ID时还会定位该回复。

规则右侧使用与其他设置一致的开关；开关左侧三点菜单提供编辑和移除。历史标题右侧“选择”进入多选，可批量删除；“一键删除”清空当前历史，操作前显示数量并确认。选择时隐藏原帖/确认回复操作，避免误触发送。删除取消尚未开始发送的任务，不会删除贴吧里的评论；已发出的请求无法撤回。被删除任务的标题、关键词、消息等内容移除，仅按账号保留最小帖子ID防重标记，重新扫描或晚到的回执不会使记录恢复或重复回复。

修改、停用或删除规则会取消该规则已有的待确认/等待任务，并保留历史记录；更换规则贴吧会重新建立基线。退关注后不再发送该吧的待执行任务。切换或退出账号会取消旧会话的运行。

发送前持久化任务占用状态，并再次核对账号、规则版本、关注状态和任务状态。无法确认发送结果、发送中断或失败时暂停自动回复，不自动重试；请从记录打开原帖确认，避免重复评论。关闭应用或网络中断时尚未发出的延迟任务重新转为待确认。这里的去重以本机任务记录为准，清除应用数据或在另一台设备独立配置会失去共享去重能力。

每账号最多20条规则、每规则最多30个关键词（各100字）、消息最多10000字；历史最多5000条，单次未完成补扫最多记录10000个帖子。达到存储上限会暂停并保留未完成扫描位置，不静默丢弃任务。分页每轮处理最多3页并保留进度，下一轮刷新第一页后继续；不能以接口不足20条作为到达旧缓存的依据。

## 平台边界与验证

安卓数据同步前台服务有系统运行时限，Android 15及以上通常为后台每24小时合计6小时；到时停止，重新打开补扫。iOS后台刷新由系统调度，不能保证固定频率。参考[Android前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout)和[Apple后台任务说明](https://developer.apple.com/documentation/uikit/using-background-tasks-to-update-your-app)。

以Android JVM回归和Swift生产核心的模拟后端验证基线、延迟、标题/正文命中、补扫确认、持久化、提醒去重、分页、账号/规则切换、退关注及未知结果不重发；历史删除还覆盖防重标记、旧文件兼容、待发送取消和晚到回执不恢复。iOS应用与测试目标编译、Android原生测试编译与Lint另行检查。2026-10-29的图标/规则操作整理及历史删除仅本地修改，未替换现有1.2安装包；SQLite原生持久化用例仅编译，未做本轮设备UI或长期后台验收。
